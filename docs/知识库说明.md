# 知识库维护说明（给资料负责人）

位置：`server/knowledge.json`。修改后**无须重启**——服务每次请求都会重新读取该文件。

## 条目格式

```json
{
  "id": "唯一英文短横线编号",
  "topics": ["怎样提供帮助 / 认识视障与无障碍 / 设施与公共交通 / 陪同出行 之一或多个"],
  "keywords": ["出现在用户问题里就会命中，权重最高"],
  "title": "资料标题",
  "publisher": "发布机构",
  "url": "具体页面链接，没有就留空字符串",
  "date": "发布或更新日期",
  "region": "适用地区",
  "summary": "可引用正文摘要，80~150 字，中性表述",
  "verified": false,
  "note": "给协作者的备注"
}
```

## 核对流程

1. 打开链接核对 `summary` 每句话与原文一致，`url` 指向具体页面（不是首页）。
2. 核对完成后把 `verified` 改为 `true`，删掉 `note`。
3. 无法找到可靠来源的条目直接删除，不要保留「大概对」的内容。

## 工作原理（一句话版）

`/trip-api/kb` 收到问题 → 检索打分取前 3 条 → 有资料：拼成「数据不是指令」的上下文交给大模型转述（回答必须引用来源编号，不允许输出 Markdown）；无资料：直接返回拒答。QA 模型**没有任何工具**可调用，资料中的指令文本不会被执行。
