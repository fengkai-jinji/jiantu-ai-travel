# 见途比赛版：围绕一次出行的 AI 协作界面

状态：交互设计方案与可运行原型，不是已实现的业务升级。2026-11-09。
范围：用户批准依据评分表优化设计；真源为最新版，3D与默认丰富动效保留，原业务代码未修改。原型均为明确标注的示例，不发送照片/位置/聊天或调用API。

## 设计取舍

比较三方向：①继续独立页面增加特效；②全屏聊天吞并所有功能；③以一次出行为主线，保留专门的感知与知识页面，共享出行上下文。采用③：既能展示工具能力，也保留表单确认、错误恢复和无障碍操作。沿用绿色米白、少量暖金、实体3D；深绿代表操作与选中，金色代表待核实，不把金色当作安全保证。

## 主线与页面

出行准备：需求输入 → 缺少位置则确认地点 → 查看真实候选 → 用户选定店铺 → 路线比较 → 行前核实。推荐必须解释偏好与数据依据，不推断店铺符合忌口、预算或无障碍条件。

感知页面：保留现有3D空间舱作为等待输入的示意场景；真实输入后显示检测画面，侧栏区分当前帧检出、连续帧状态、播报状态和能力边界。感知只观察，不指挥过马路，也不把检测类别自动作为导航路线。

知识页面：问题 → 检索结果 → 回答与逐条来源。来源展示标题、发布方、具体链接、日期、适用地区、核验状态。无资料和服务失败分别呈现；只有经过核对的条目才能标记已核验。过期设施状态和实时营业情况不能由常识补全。

每页顶部共享本次出发地、目的地和偏好摘要；切页不清空任务。当前地点改变需使旧路线失效，同时保留历史聊天及明确说明；不自动恢复不适用路线。保持首页、室内寻物和知识页的独立入口。

## Agent 状态与交互（待接入）

请求前：校验输入与确认位置。请求中显示真实阶段事件（接收、查地点、比较路线、整理回答），工具开始/结束事件由服务器发出；不得按时间伪造进度。最终卡片只来自工具响应。

建议事件契约：requestId、eventId、type、tool、status、message、payload；type覆盖accepted、tool_start、tool_end、answer_delta、result、error、done。前端忽略旧requestId与重复eventId。服务器只输出允许展示的工具摘要与答案，不输出内部思维或隐藏推理。

取消立即恢复操作，保留旧有效结果；后台能否取消另行说明。断流和错误保留已经收到的内容并标明未完成，不将半条答案作为完整结论。暂不自动重放有副作用的工具。

现有简单附近餐饮直查保留快路径；明确显示地图直查，与LLM规划区分。Function Calling已满足规则中“或”的工具集成路径，不为了技术名词额外堆MCP。

## 感知可靠性（先于新增模型能力）

1. 将路线外改为画面边缘描述，没有路径与运动证据时不得据此认定安全或静默近级车辆。
2. 去掉未标定的准确米数表达，明确画面位置/大小规则产生的提醒级别；照片是单帧，实时输入才有连续帧状态。
3. 将实时目标的连续命中状态按类别与方位维护，并测试漏帧/级别变化/消失；连续确认会增加延迟，危险阈值与确认策略要在独立数据上评估，不能把两帧本身当作可靠性证明。
4. 语音区分新危险抢占和同一警告重播，当前同一句未结束时不重复取消自身；关闭自动播报立即停止，文本提示始终保留。
5. 页面和一键启动检查地图、室内、室外分别就绪，显示失败的具体能力，不以地图成功代表全部就绪。

原型用手动状态切换演示上述布局，不模拟真实摄像头安全能力。

## 知识库与RAG

现状核对：本轮读取22条，标记核验2条。不能直接把其余20条改成true。逐条核对后可保留、修正或剔除；无法核验时清楚标识，不把其当作确定事实。

先建立带标准来源和预期拒答的题集，随后比较当前词匹配与候选语义/混合检索；是否引入向量索引以题集收益为依据。保留检索不到即拒答，分别记录检索命中、引用正确、回答支持度、适用地区与时效。不是安装向量数据库即证明RAG升级。

## 动态与无障碍

默认：任务节点连线流动、结果卡短距离入场、选中方案空间展开、示意3D运镜；不要以动画延迟显示回答。新增提示不依赖颜色，当前步骤以文字及aria-current表示。

站内减少动态或系统偏好：立即撤销非必要JS/CSS运动，静态呈现完整内容；动作、结果与图标不删。键盘能完成输入、选店、选路线与查来源，错误可被读屏感知。流式片段不逐字高频朗读，优先播报阶段和完成摘要。

## 验收与实施顺序

第一阶段：感知规则/语音问题、来源治理、服务就绪。验收边缘车辆、单帧/连续帧、重复危险、关闭语音、没有依据的问答、服务失败。
第二阶段：共享一次出行任务与真实事件流。验收补问、查询、确认、切换偏好、取消/断流/重试、切页保留、迟到响应抑制。现有直查不退化。
第三阶段：基于题集选择检索改进，补独立模型评测、读屏和手机/语音实测；展示实际统计，不能把mock测试当作真实业务证明。
第四阶段：完善README、开源/模型/素材署名、依赖与环境模板、真实Git历史；录制5–8分钟1080p视频和30页内PDF。在线演示需单独确认评审期间可用性，部署不是本轮授权的既成事实。

所有阶段测试区先行，验收后同步最新版与完成区，发布前检查并发修改。不可伪造历史提交、核验状态、工具轨迹或评测数据。
