# 见途运行与交付说明

本文按当前启动脚本和运行源码整理。所有命令均在项目根目录执行，配置只填写到本机 `.env`，不把真实 Key 放入公开仓库。不要将安装、构建或状态接口成功等同于业务验收通过。

## 1. 环境与依赖

- Node.js：建议 22.12 或更新的受支持版本。当前 Vite 锁定依赖的引擎范围为 `^20.19.0 || >=22.12.0`，不应笼统写作 Node 18+。测试命令使用 `--experimental-strip-types`，还需确认所选 Node 支持该参数。
- Python：建议 3.10 或 3.11，使用独立虚拟环境。这里给出运行建议，未声明所有 Python、CUDA 或显卡组合都完成兼容测试。
- 浏览器：支持摄像头和 Web Speech 的浏览器；实际能力、权限与可用语音因浏览器和系统而异。先在本机 `127.0.0.1` 测试。

```powershell
node --version
python --version
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`npm ci` 按 `package-lock.json` 安装前端依赖。Python 清单包含源码直接使用的 `ultralytics`、`opencv-python`（导入名 `cv2`）、`numpy`、`torch`；没有 Flask 或 LangChain。地图、Agent 与知识问答通过 Python 标准库提供 HTTP 服务和外部请求。Python 清单没有固定全部传递依赖版本，安装成功后仍应在目标机器完成推理验收；GPU 加速还取决于 PyTorch 与本机驱动环境。

## 2. 配置

```powershell
Copy-Item .env.example .env
```

仅首次创建时执行，已有 `.env` 时直接编辑，避免覆盖自己的配置。

| 配置项 | 用途 |
| --- | --- |
| `AMAP_MAPS_API_KEY` | 高德 Web 服务接口 Key；地点、路线、周边搜索使用 |
| `LLM_API_KEY` | 大模型 API 密钥 |
| `LLM_BASE_URL` | 大模型接口地址，示例为智谱接口 |
| `LLM_MODEL` | 模型名，示例为 `glm-4.6` |
| `TOKEN_DAILY_LIMIT` | 单个后端进程内的按日 Token 用量护栏，示例 80000；不是账单或持久化配额管理 |
| `YOLO_BACKEND_URL` | Vite 室内代理目标，默认 `http://127.0.0.1:8765` |
| `OUTDOOR_BACKEND_URL` | 可选室外代理目标，默认 `http://127.0.0.1:8767`；当前示例未列出，可按需补到本机配置 |

`.env.example` 只保存空密钥与示例值。真实 `.env` 已列入忽略规则，交付和提交前仍须核对待上传文件。不要给密钥加 `VITE_` 前缀或写入前端源码。修改代理目标后重启 Vite。地图代理目前固定转到本机 8766，不存在对应的可配置地图目标项。

缺少地图 Key 时地图调用会报配置错误；缺少完整大模型配置时 AI 能力受限。知识问答有命中资料时可只展示资料卡，无匹配则拒答。识别服务不依赖地图或大模型 Key。

## 3. 启动方式与端口

| 端口 | 进程入口 | 前端代理路径 |
| --- | --- | --- |
| 5173 | `npm run dev` | 网页入口 |
| 8765 | `python demo/app.py` | `/api`，不移除路径前缀 |
| 8766 | `python server/maps.py` | `/trip-api`，不移除路径前缀 |
| 8767 | `python server/outdoor.py` | `/outdoor-api`，转发时移除此路径前缀 |

### Windows 一键启动

```powershell
$env:JIANTU_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
$env:JIANTU_NODE = (Get-Command node).Source
.\启动项目.ps1
```

`JIANTU_PYTHON`、`JIANTU_NODE` 接受解释器的可执行文件路径。未设置时，脚本会先尝试原开发机器的 `F:\Miniconda\envs\yolo\python.exe` 与 `F:\NodeJS\node.exe`，不存在再使用 PATH 中的 `python`、`node`。换机器建议显式设置，避免误用未安装依赖的解释器。

脚本跳过已有监听的端口，隐藏启动窗口，将日志写到项目根目录的 `backend`、`outdoor`、`maps`、`frontend` 对应 `.log` 和 `-error.log` 文件。它最多等待约 40 秒检查三个代理状态接口，成功后打开 `http://127.0.0.1:5173/#trip`。若同端口被其他进程占用，不能因为脚本跳过启动就认为进程正确；应核对状态内容和服务日志。

### 手动启动

分别打开四个终端，各执行一条命令：

```powershell
.\.venv\Scripts\python.exe demo/app.py
.\.venv\Scripts\python.exe server/maps.py
.\.venv\Scripts\python.exe server/outdoor.py
npm run dev
```

上面四条命令是四个独立长驻进程，不能等待上一条退出后才启动下一条。浏览器访问 `http://127.0.0.1:5173/`。独立室内终端另可访问 `http://127.0.0.1:8765/`，该终端的视频、手机流和预警逻辑不等于主网页的功能流程。

`server/indoor.py` 是 8765 的备选纯图片接口，与 `demo/app.py` 只能二选一；它不提供独立 demo 的视频流功能。一键脚本固定使用 `demo/app.py`。

## 4. 模型文件与口径

| 用途 | 当前路径 |
| --- | --- |
| 默认室内 v3 | `model-training/indoor/products_v3/weights/best.pt` |
| 室内回退 v2 | `model-training/indoor/products_v2/weights/best.pt` |
| 室外四类 | `便携推理包/runs/multi4v6c_yolov8n/weights/best.pt` |

这些路径在当前交付目录存在，迁移时保持相对路径。室内请求默认 `mode=project` 使用 v3，指定 `mode=v2` 使用回退权重。两版均为 `bottle/chair/door` 三类，瓶与杯合并显示。「全部目标」只是前端选择，不新增类别。独立 demo 还声明了 `general` 模式，但其 `models/yolo26n.pt` 未随当前目录提供，不属于开箱可用的项目三类能力。

室内权重按需加载；室外服务在创建检测器时加载权重，状态请求也可能触发加载。首次状态或推理可能较慢。HTTP 服务响应只证明相应请求成功，不能代替上传真实图片的模型验证。

室内评测结论以 [REPORT.md](../model-training/indoor/eval/REPORT.md) 为准：v3 优势集中在近景椅子召回，整体 mAP 几乎持平，瓶类跨域效果弱，门类样本不足，不能宣传所有类别精度提升。训练和干净集评测脚本仍引用仓库外的 `F:/归档/数据集与标注/YOLOv8` 数据目录；仓库提供记录与权重，不含全部复现数据。评测使用的 Ultralytics 版本记录为 8.4.33，不等于未锁定依赖清单自动安装的版本。

室外级别依据二维框规则，不是实际距离测量。`off_route` 仅是边缘位置标记，前端不据此静默边缘车辆。实时两帧确认只比较类别与画面方位，不做实体跟踪。大模型微调、向量检索没有作为当前线上实现部署。

## 5. 检查与交付

源码检查命令：

```powershell
npm test
npm run build
.\.venv\Scripts\python.exe -m unittest discover -s server -p "test_*.py"
.\.venv\Scripts\python.exe -m unittest discover -s demo -p "test_*.py"
```

运行检查应分别记录事实：

1. 服务检查：从 5173 请求 `/api/status`、`/trip-api/status`、`/outdoor-api/status`，核对 JSON 内容与日志。状态通过后继续检查实际业务。
2. 真实推理：各上传一张室内、室外照片，核对返回模型、目标框、无目标反馈；不要使用模拟模式替代。
3. 外部接口：确认地点候选、路线比较与 AI 回答使用真实配置且有结果，不能以“已配置”代替调用成功。
4. 浏览器操作：人工核验摄像头授权与停止、语音开启与关闭、键盘焦点、辅助设置和读屏体验。自动化测试不能证明这些全部通过，媒体、语音或硬件流程的局部实测也不代表完整端到端验收。

`npm run build` 输出 `dist/`。构建文件本身不包含 Python 服务、模型推理或服务器密钥；单独部署静态目录不会自动具备全部功能。`npm run preview` 可在本机预览构建，并使用当前 Vite 代理配置，但不等同于生产部署方案。

交付至少保留源码、锁文件、`.env.example`、Python 依赖清单、启动脚本、知识库和三个项目权重及其相对路径。不要上传 `.env`、`node_modules/`、运行日志、`demo/uploads/` 或本机缓存。页面截图和自动化结果须与最终交付版本对应；构建、测试、接口、GUI 的通过情况分别记录，尚未实测的流程明确标记待核验。


## 训练架构口径

室内 products_v2 与 products_v3 的 args.yaml 均记录基模型为 yolo11s.pt。室外使用 multi4v6c_yolov8n 权重。Ultralytics 运行库版本、YOLO模型家族与项目版本v3是不同概念，不能都写成YOLOv8。
